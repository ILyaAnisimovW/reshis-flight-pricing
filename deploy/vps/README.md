# Oracle Always Free: подготовка VPS

Статус: подготовлены конфигурации, сервер Oracle не создан и публичный деплой не выполнен. После уточнения проживания владельца в РФ Oracle исключён из текущего плана: [официальное уведомление Oracle](https://www.oracle.com/corporate/conflict-in-ukraine/russia/) сообщает об ограничении предоставления и использования сервисов в России. Нижеследующий сценарий Oracle сохранён как справочный; systemd и конфигурация reverse proxy подходят для другого совместимого Linux VPS. Старый KEY/Gourmet Box размещён на Render; найденные старые SSH-адреса не подтверждают наличие Oracle.

## Виртуалка

В OCI Console выбрать домашний регион и Compute Instance с пометкой Always Free. Согласно проверенной 14.11.2026 документации, бесплатный аккаунт допускает суммарно до 2 OCPU и 12 GB RAM Ampere A1. Для этого приложения достаточно начать с 1 OCPU / 2 GB RAM при доступности такой конфигурации. Перед созданием проверить бесплатный статус выбранных compute, boot volume и дополнительных ресурсов в консоли; не включать платные опции. Операционная система — Ubuntu 24.04 LTS для выбранной архитектуры. Если бесплатных мощностей нет, дождаться доступности, не заменять машиной с оплатой без согласования.

Зарегистрироваться и принять условия Oracle должен владелец аккаунта. Приватный SSH-ключ хранить локально; публичный ключ добавить при создании машины. После создания нужны IP, имя SSH-пользователя и локальный путь к приватному ключу. Постоянный диск хранит H2, но резервная копия всё равно нужна: неактивные Always Free экземпляры могут освобождаться Oracle.

## Развёртывание после подключения

1. Проверить ОС, свободные память/диск, текущие сервисы и порты. Установить Java 21 для архитектуры VM. Собирать JAR локально через Gradle Wrapper, на VM передавать готовый JAR и проверить SHA-256. Запуск JVM одинаков для ARM64 и x86_64; JRE должен соответствовать VM.
2. Создать системного пользователя `aviaprognoz` без shell-входа. Каталог `/opt/aviaprognoz/releases` хранит JAR с именем по хешу, владелец root. `/opt/aviaprognoz/current.jar` — ссылка на выбранный релиз. Не перезаписывать открытый JVM файл JAR; для обновления загрузить новый файл и переключить ссылку перед перезапуском.
3. Установить `app.env.example` как `/etc/aviaprognoz/app.env`, права 0600, владелец root. Заменить заглушку `DB_PASSWORD` случайным секретом без вывода в лог и не менять её при обновлениях. Существующую локальную базу с пользователями автоматически не публиковать. H2 запускается одной репликой и хранится в `/var/lib/aviaprognoz`; этот каталог управляется systemd через StateDirectory.
4. Установить `aviaprognoz.service` в `/etc/systemd/system`, выполнить `systemctl daemon-reload` и `systemctl enable --now aviaprognoz`. Проверить `curl --fail http://127.0.0.1:18092/api/ready`: ожидаются status UP и forecast_rows 155. Java слушает только loopback; наружу порт 18092 не открывать.
5. Выбрать домен, направить DNS на VM, добавить блок из `Caddyfile.example` в конфигурацию обратного прокси. Сохранить уже работающие сайты сервера. Для автоматического HTTPS обеспечить доступность TCP 80/443 в OCI и firewall ОС. SSH ограничить IP администратора. Проверить конфигурацию прокси до reload. Если на машине уже есть nginx/Caddy, адаптировать текущий proxy, не занимать его порты вторым сервером.
6. Проверить публичный HTTPS, logo-orbit.png, каталог из пяти направлений, расчёт, CSRF, регистрацию/вход/выход. Взять отдельную тестовую учётную запись и проверить её вход после перезапуска приложения. COOKIE_SECURE=true оставить для HTTPS. Проверить отсутствие публичного доступа к H2 и env-файлу.
7. Для резервной копии файловой H2 остановить только `aviaprognoz`, скопировать `/var/lib/aviaprognoz/accounts.mv.db` в защищённое хранилище и запустить сервис. Копирование активного файла базы не считать проверенной резервной копией. Перед обновлением сохранить предыдущий релиз для отката; базу не удалять.

Проверки Linux systemd, Caddy и реальной VM пока не выполнялись: в текущей Windows-среде отсутствует подключённый Oracle-сервер. Создание VM, загрузка данных и публичная ссылка подтверждаются отдельно после фактического выполнения.
