# Запуск, проверка и эксплуатация

## Локально

Требуются JDK 21 и доступ к Maven/Gradle при первой сборке. Gradle Wrapper включён; отдельный системный Gradle не нужен.

```powershell
.\gradlew.bat clean test bootJar --no-daemon
java -jar build/libs/reshis-app-1.0.0.jar
```

Открыть http://localhost:8080. По умолчанию H2 file хранится в `./data/accounts`; запускать из выбранного постоянного рабочего каталога. На Linux: `chmod +x gradlew && ./gradlew clean test bootJar --no-daemon`. Node не нужен для runtime опубликованного интерфейса; отдельные проверки frontend имеют свои зависимости.

## Публичное окружение

Docker / Java 21 на Render Free; PostgreSQL на Neon. DB_URL, DB_USER, DB_PASSWORD задаются в окружении. Профиль `render` обязателен для внешней БД; `PORT` задаёт порт. JDBC URL должен требовать проверку TLS-сертификата. Не копировать реальный URL с паролем в команды или документы. Подробности: [deployment.md](deployment.md).

## Проверка перед демонстрацией

1. GET `/api/health`: процесс отвечает UP.
2. GET `/api/ready`: прогноз загружен, 155 строк. В опубликованном срезе readiness ещё не доказывает доступность аккаунтов.
3. GET `/api/catalog`: пять маршрутов, по 31 дате.
4. Выполнить расчёт по [примеру](integration-guide.md); проверить 9000 → 854/854, 8000 → 995/900 на MOW-AER 01.06.
5. Проверить регистрацию, login, защищённую памятку и logout с демонстрационным аккаунтом.

PowerShell-проверки исходного проекта: `scripts/verify-http.ps1` и `scripts/verify-reference.ps1` с `-BaseUrl`. Они могут создавать тестовый аккаунт или записывать локальные протоколы — сначала прочитайте сценарий и выберите тестовое окружение. Не запускайте нагрузочное тестирование бесплатного сервиса перед сдачей.

## Отказы

| Симптом | Проверка и действие |
|---|---|
| Первый запрос долго ждёт | Бесплатный экземпляр может пробуждаться; дождаться запуска и проверить Render logs |
| Не стартует после замены CSV | Проверить схему, даты, дубликаты и SHA; вернуть предыдущий проверенный артефакт |
| Расчёт работает, вход нет | Отдельно проверить Neon и переменные БД; readiness старой версии не проверяет SQL |
| После рестарта нужно войти снова | Ожидаемо: сессия в памяти; пользователь в PostgreSQL остаётся |
| 403 после входа/выхода | Получить новый CSRF в той же cookie-сессии |
| После деплоя старый интерфейс | Проверить выбранную ветку/commit, статус deploy и кэш браузера |

## Обновление и откат

Перед деплоем зафиксировать SHA исходников, SHA CSV, успешную сборку и проверки. В опубликованной конфигурации Public Git Repository обновление выполняется через Manual Deploy; push сам по себе не доказывает обновления сайта. Для отката выбрать предыдущий известный рабочий commit/артефакт в Render и проверить health, CSV/API и аккаунты.

Пользователи хранятся отдельно от приложения. Перед изменением схемы БД сделать резервную копию средствами PostgreSQL/провайдера и проверить восстановление в отдельной базе. Автоматическая проверенная процедура backup/restore и непрерывный мониторинг в этом учебном проекте не заявляются.

## Ограничения платформы

Один экземпляр, сессии в JVM, бесплатные лимиты и возможный cold start. Нет заявленного SLA, высокой доступности или измеренного предела нагрузки. Квоты и тарифы провайдеров меняются; проверять их в аккаунтах перед эксплуатацией.
