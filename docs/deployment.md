# Размещение на Render

Выбранная схема: бесплатный Render Web Service (Docker, Java 21) и отдельная PostgreSQL в Neon Free. Приложение отдаёт интерфейс и API с одного origin. Oracle исключён после уточнения проживания владельца в РФ: [официальное уведомление](https://www.oracle.com/corporate/conflict-in-ukraine/russia/).

## Подготовленная конфигурация

`render.yaml` описывает только Web Service с `plan: free`, регионом Frankfurt и проверкой готовности `/api/ready`. Платные диски и дополнительные сервисы в нём отсутствуют. JVM ограничена heap 256 MB для экземпляра с 512 MB RAM; потребление памяти всего процесса необходимо проверить на хостинге. Файл сам по себе не подтверждает создание ресурса или успешный деплой.

Профиль `render` требует `DB_URL`, `DB_USER`, `DB_PASSWORD` и PostgreSQL JDBC driver. Без внешней базы приложение завершит запуск с ошибкой, а не переключится на H2 во временной файловой системе. При первом успешном подключении существующий idempotent SQL приложения создаёт таблицу users; локальные пользователи автоматически не копируются в облако. Локальный профиль H2 сохранён.

Переменные сервиса:

| Имя | Значение |
|---|---|
| SPRING_PROFILES_ACTIVE | render |
| JAVA_TOOL_OPTIONS | -Xms32m -Xmx256m -XX:+ExitOnOutOfMemoryError |
| DB_URL | jdbc:postgresql://HOST/DATABASE?sslmode=verify-full |
| DB_USER | Роль только для базы этого проекта |
| DB_PASSWORD | Секрет роли, хранится только в настройках среды |

HOST/DATABASE берутся из фактически созданного проекта Neon. Пароль не включать в JDBC URL, Git, скриншоты или журнал команд. Доступ роли к базе, её регион, бесплатный план и SSL проверяются при подключении. Render сам задаёт PORT; приложение читает его. HTTPS завершается на Render, профиль включает Secure cookie и обработку proxy headers. Максимум 3 соединения, minimum-idle 0, idle-timeout 60 секунд ограничивают расход подключений простаивающего сервиса.

## Порядок публикации

1. Запустить `gradlew.bat test bootJar --no-daemon` и `node --test tests/frontend/unit-check.cjs`. Зафиксировать и опубликовать проверенную ветку с Dockerfile, render.yaml, исходниками и ассетами. Базы, runtime и секреты в Git не включать.
2. В существующем аккаунте Neon выбрать Free и создать отдельную базу проекта. Если требуется вход или принятие новых условий, эту часть проходит владелец аккаунта. Не менять базы других проектов.
3. В Render создать Docker Web Service из публичного репозитория `https://github.com/ILyaAnisimovW/reshis-flight-pricing`, выбрать фактически опубликованную ветку, регион Frankfurt и именно Free. При ручном создании повторить переменные из render.yaml. Health check: `/api/ready`.
4. После успешной сборки проверить HTTPS, главную страницу и логотип, `/api/health`, `/api/ready` (155 строк), каталог (5 направлений, 31 дата), расчёт с CSRF и аккаунты. После перезапуска сервиса проверить вход в тестовую учётную запись: запись должна сохраниться в PostgreSQL. Сама серверная сессия при перезапуске теряется — повторный вход ожидаем.
5. Записать фактическую публичную ссылку, commit и результаты проверок ниже. Не считать успешную локальную сборку подтверждением публичного деплоя.

## Бесплатные лимиты

Render Free засыпает после 15 минут без входящего трафика; следующий заход может ожидать запуска примерно минуту. Файлы в контейнере не сохраняются при перезапуске. Бесплатные часы (750 в месяц) общие для workspace: другие Web Services расходуют ту же квоту. Учтены также лимиты трафика и сборок. Бесплатный Render Postgres истекает через 30 дней, поэтому не выбран как постоянная база этого проекта. Не включать платные upgrades без отдельного решения владельца.

Neon Free имеет свои лимиты хранения/compute и может приостанавливать compute при бездействии. Бесплатность не означает отсутствие ограничений или гарантированную доступность. Проверенные условия: [Render Free](https://render.com/docs/free), [Render Docker](https://render.com/docs/docker), [Blueprint](https://render.com/docs/blueprint-spec), [Neon pricing](https://neon.com/pricing), [Java/PostgreSQL](https://neon.com/docs/guides/java).
