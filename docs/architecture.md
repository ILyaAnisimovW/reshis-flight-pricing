# Архитектура

Браузер → fetch с cookie и CSRF → Spring Security → REST controller → Forecast → CSV из classpath. Контроллер регистрации использует JdbcTemplate и PasswordEncoder → H2 file. База и сессия решают разные задачи: база переживает остановку, сессия — нет.

`src/main/java/app` — приложение, расчёт/CSV, HTTP и безопасность; `src/main/resources/static` — HTML/CSS/JS; `src/main/resources/data` — проверяемые CSV внутри JAR; `src/test` — JUnit и MockMvc; `scripts` — настоящие HTTP-проверки; `docs` — объяснения и доказательства; `.github/workflows` — Linux CI.

Расчёт отсутствует в JavaScript. При вводе предыдущий результат помечается устаревшим и остаётся видимым, запрос отменяется и дополнительно проверяется его порядковый номер: старый ответ не заменяет новый. Доступная таблица дублирует SVG.

Граница упрощения: небольшой проект использует DTO регистрации и JSON дерево расчёта для строгого различения JSON number/string/boolean. Таблицу пользователей создаёт контроллер при старте; для развития проекта её стоит вынести в миграцию, а регистрацию — в отдельный сервис. Это не микросервисная система.
